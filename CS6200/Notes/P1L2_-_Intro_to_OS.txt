==== 2. Introduction to OS ====
	OS like a shop manager:
		* Directs operational resources:
			* Control use of employee time, parts, tolls
		* Enforces working policies:
			* Fairnes, safety, clean-up
		* Mitigates difficulty of complex tasks:
			* simplifies operation & optimizes performance

	The OS does:
		* Direct opeartional resources
			* Control use of CPU, memory, peripheral devices
		* Enforce working policies:
			* Fair resource access, limit to resource usage
		* Mitigate difficulty of complex tasks:
			* Abstract HW details (system calls)

==== 3. What is an OS ====
	Computer consists of CPU (multiple core), main memory, wifi card, GPU, disks:
		HW used by multiple applications

		OS sits between applications and hw

		Applications
		OS
		HW

	OS:
		Hides hw complexity (how they are accessed to read/write a file, etc)
		Resource management (Manages the HW)
		Provide isolation & protectoin (Access to HW is managed correctly)

==== 4. Operating System - Definition ====
	An OS is a layer of SW that:
		* Has priviledge access to HW
		* Hides HW complexity
		* Manages HW on behalf of application according to predefined policies
		* Ensure applications are isolated and protected from one another.

==== 8. OS Elements ====
	Abstractions
		Process, thread, file, socket, memory page
	Mechanisms
		Create, schedule, open, write, allocate
	Policies
		Least Recently Used (LRU), Earliest Deadline First (EDF)
	

==== 9. OS Elements - Example ====
	Memory management Example

	Abstractions
		Memory page (addresable region of memory, eg. 4K)
	Mechanism
		To operate on that page (Allocate in D-RAM and map to a process)
		Process then can access the memory
		Over time, this page can be move around in physical memory, or even
		moved to physical disk if need to make RAM available for other processes
	Policies
		Least Recently Used - LRU
			OS Policy to move pages from RAM to Disk (Swapping - DRAM to Disk and Viceversa)

==== 10. OS Design Pricinples ====
	Separation of mechanism & policy
		Implement flexibl mechanisms to support many policies
		e.g. LRU, LFU, random

	Optimize for common case
		Where will OS be used?
		What will be executed on that machine?
		What workload requirements?

==== 12. System Call Flowchart ====
	Executing User Process
		System Call
			Changes execution context from User proces to OS Kernel (How?)
			Passes arguments for system call (Where, How)
			Jump to some location in the kernel's memory to execute instruction for system call.
			After system call completion, return result and control to calling process.
				changes context from Kernel to user mode
			System call is an expensive operation

==== 16. Monolithic OS ====
	Every service is part of the OS.

	Advantages:
		Everything is included.
		Inline compile time optimizations

	Disadvantages
		Customization, portability, memory footprint

==== 17. Modular OS ====
	Basic services are part of OS. Rest can be added as a module.
