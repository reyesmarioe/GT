==== 3. Process vs Threads ====
	Process
		Represented by address space
		Address space contains all the virtual to physical mapping
		Represented by it execution context:
			Values of register, stack pointer, program counter

		OS keeps all this info in the PCB

	Threads
		Represent multiple execution contexts
		Part of the same address space, share virtual to phys mappings
		Shared code, data, files

		However, probably executed diff. instructions, access diff. portions of that address space.
		Each thead has a different program counter, stack, thread-specific register.
		Each thread needs different data structures to represent them.
		**PCB** is more complex, includes per thread context data
	{{./pasted_image001.png}}


==== 4. Benefits of multithreading ====
	**Parallelization**
		Single process with multiple threads, each processing different data of an input array.
		All threads execute the same code, but not necessarily the same instruction at some point
		This speed up the processing of the input array (Parallelizatin processing)
	**Specialization**
		Multiple threads executing different portions of the code for specialized tasks.
		Each thread can have its own priority, lower or higher
		Possible to have hot cache, which gives higher performance.
	**Efficiency**
		Lower memory requirements, faster IPC

==== 12. Mutual exclusion ====
	
	Mutex is a lock, used whenever accessing shared data between concurrent threads.
		Also called acquired mutex.

		Mutex contains information about
			status
			blocked threads
			owner

	{{./pasted_image012.png}}


	**Critical Section**
		Portion of the code protected by the mutex
		Any operation that only one thread can execute at any one time
		After exiting the critical sectino, the mutex is release, other threads can the acquire the mutex

==== 16. Condition Variables ====
	Control the behavior of concurrent threads.

	Here the consumer acquires the lock and checks if list if full. If not, threads suspends itself and it enters the Wait state and releases the mutex.
		Thread is then waiting on the Signal.
		Once signal is received, it automatically acquires the mutex again, does some work and releases the mutex.

		Consumer
			Locks the mutex
			Checks on condition
			If condition not ready, suspend and Wait. Releases mutex
			When signal received, locks mutex
			Does its work
			Releases the mutex

	The producer keeps working and checking if the list is full. When it is, it Signals the waiting threads
