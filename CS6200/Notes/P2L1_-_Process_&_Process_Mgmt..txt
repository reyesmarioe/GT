==== 3. What is a process? ====
	Application - Program on disk, static entity

	Process - State of a program when executing, loaded in memory, active entity.

==== 4. What does a process look like? ====
	Process encapsulates stack, heap, data, text (code).
		This is also called the address space of a process.

		Text - Static staten when process first loads
		Heap - Dynamically created during execution
		Stack - Grows and shring (LIFO) during execution.

==== 5. Process address space ====
	Address space - in memory representation of a process.
						Memory uses virtual addresses, because they dont have to correspond to
						actual location in physical memory.

	**Vo - Vmax = Address space**

	Memory Managment HW and OS maintain a mapping (**Page Tables**) b/w Virtual Addresses and Physiscal Addresses.

	By using this memory mapping, it decouples the data in the process on how it's represented in physical memory
	It allows to maintain physical memory management simple, it's not dictated by data layout of the executing process.

==== 10. How is a PCM used? ====
	While P1 is runnig, CPU regs holds values of PCB.P1
	When P1 is interrupted, OS saves PCB.P1.
	Then P2 start runnig, the OS updates the CPU registers with PCB.P2

	Context switch - Saving PCB values for 1 process and restoring PCB values for other process so that i can start running.

==== 11. Context Switch ====
	Mechanism used by the OS to switch the execution from one proces to other process.

	This is an expensive of operation
		Direct cost - Number of cycles for load 2 store instructions

==== 13 Process Lifecycle States ====
	Processes can be:
		Running or Idle

	
	When processes is created is in state NEW
		Creates PCB, checks permissions and available resources
	If all ok, it moves to READY. 
		Ready to start executing, It waits in this state until scheduler is ready to move it to a RUNNING state
	When process is scheduled on CPU by scheduler it is now on RUNNING state.
	From here, the process could be:
		Interrupted, which will move the process to a READY state. OR
		If process needs to wait for a long process to complete, it's moved to a WAITING state
			Once operation completes it moves to READY state.
	Once the process completes its execution of fails due to error, it will moved to TERMINATED state.

==== 17. Role of the CPU scheduler ====
	Multiple ready process in queue. Which one to run?

	CPU Scheduler determines which one of the currently ready processes will be dispatched to the
	cpu to start running and how long it should run for.

	**preempt** - Interrupt and save current context
	**Schedule** - Run scheduler to choose next process
	**Dispatch** - Dispatch processes and swtich into its context

	OS Must be efficient. Should minimize time running above processes.

==== 21. Inter Process Communication ====
	IPC mechanisms
		Transfer data/info between address spaces
		Maitain protectin and Isolation
		Provide flexibility and performance

	{{./pasted_image024.png}}

	Message Passing IPC

	OS provides communication channel (shared buffer, etc)
	Processes write/read msgs to/from channel
	Advantages
		OS manages the channel
	Disadvantages
		overhead, calling into the kernel
	{{./pasted_image025.png}}

	
	Shared Memory IPC

	OS establishes a shared channel and maps it into each process address space
	Processes directly read/write from this memory

	Advantages
		OS is out of the way

	Disadvantages
		No standard way or set of api to use, code reimplementation
